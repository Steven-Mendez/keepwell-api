# 0002. Hono for HTTP

Status: accepted, November 2026

## Context

The API runs in a single Lambda behind an HTTP API, with about fifteen routes. Two of the pieces it
mounts hand over handlers built on the web-standard `Request`/`Response`: Better Auth and the MCP
SDK's Streamable HTTP transport. Cold starts are paid by the person waiting for the app.

## Decision

Hono, with `hono/aws-lambda` in production and `@hono/node-server` locally. The app is built by
`createApp(dependencies)`, so tests, local development and Lambda wire the same object, and tests
call `app.request()` without a server.

## Alternatives

- **Fastify.** The usual choice for Node on Lambda and a reasonable second. It speaks Node's
  `req`/`res`, so Better Auth and the MCP transport would need adapters in both directions. Its
  plugin catalogue doesn't matter at fifteen routes.
- **NestJS.** Solves the organisation of large teams with dependency injection and decorators, at
  the cost of one-to-three-second cold starts and validation with class-validator instead of the
  existing Zod schemas. Right in a container, wrong here.
- **No framework** (a hand-written router over `Request`). Possible, but middleware ordering, body
  limits and error handling would be re-implemented and tested by hand.

## Consequences

- Zero runtime dependencies from the framework; the bundle stays small.
- Hono owns routing, so API Gateway has a single `$default` route and a new endpoint never needs
  a Terraform change.
